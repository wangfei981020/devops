# ee/ —— 企业版组件

这个目录里的代码需要有效授权才能使用，条款见 [LICENSE](LICENSE)。

## 这个边界是什么性质的

🔴 **它是商业/合规边界，不是技术边界。**

源码随产品交付给部署方，所以门控在技术上是可以被删掉重新编译的。
这一点我们清楚，也不打算假装不是这样 —— 试图用混淆、加密等手段"加固"
只会让排障变难，而挡不住真正想绕的人。

这个目录的作用是让"绕过门控"这件事**从一次技术操作变成一次违反许可条款的行为**：
边界在哪里没有歧义，删掉了什么也没有歧义。

## 什么该放进来

只放**纯粹属于企业版**的实现。

⚠️ 被社区版功能复用的东西**不要**放进来。放进来的后果不是"多保护了一点"，
而是社区版的正常功能跟着变成需要授权 —— 那是反向的伤害。

已经因此留在外面的：

| 留在外面的 | 为什么 |
|---|---|
| `internal/dataview` | 自检、事件详情、噪音数据这层查询同时被 REST 接口和 MCP 工具调用。放进来的话，看一眼事件详情都要授权 |
| `internal/httpx` | 错误响应。它决定"失败长得像失败"，是全站纪律，与是否付费无关 |
| `internal/license` | 授权内核本身。社区版也要用它来判容量上限 |
| 检测引擎 `engine/` | 产品的核心，社区版的立身之本 |

## 目录

| 路径 | 功能项 | 说明 |
|---|---|---|
| `mcp/` | `mcp_full` | AI 接入（Model Context Protocol）。未授权时路由返回 **404**，菜单不显示 —— 需求是"看不到"而不是"看得到但用不了" |

## 未授权时的两种表现，别混用

- **404 / 菜单不显示** —— 用于"不希望对方知道有这个功能"（当前只有 MCP）
- **402 + 说明页** —— 用于"希望对方知道并考虑购买"（噪音治理、回放实验室）

选哪一种是**商业决定**，写在这里是为了让后来改代码的人不要按自己的直觉随手统一。
