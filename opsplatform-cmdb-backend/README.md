# CMDB · 运维配置管理库

把域名、证书、主机、云资源、K8s 多集群的家底统一登记在一处，并回答两个问题：
**现在是什么样**（台账 + 实时体检），以及**是谁在什么时候把它改成这样的**（审计 + 回滚）。

它要解决的是这类日常：证书还有几天到期、这个域名解析到哪、这台机器属于哪个项目、
某个集群的节点为什么不健康、上个月云上花了多少钱、昨天谁动过这条 DNS。
过去这些答案散在 GCP 控制台、Cloudflare、GoDaddy、KubeSphere、Jenkins 各处，
要登录五六个系统才能拼起来。

---

## 1. 架构

```
                    ┌──────────────── 运维平台 (opsplatform) ───────────────┐
                    │  统一登录 · 角色/权限分配 · 外部应用准入                │
                    └──────────────┬───────────────────────────────────────┘
                                   │ SSO + 权限码
┌──────────────┐            ┌──────┴───────┐          ┌────────────────────┐
│ CMDB 前端     │──/api/──▶ │  CMDB 后端    │──────▶  │ MySQL (cmdb 库)     │
│ Vue3 + EP    │            │  Go + gin     │          │ 台账 + 审计 + 快照   │
└──────────────┘            └──────┬───────┘          └────────────────────┘
                                   │
        ┌──────────────┬───────────┼───────────┬──────────────┬─────────────┐
        ▼              ▼           ▼           ▼              ▼             ▼
   注册商 API      Cloudflare   K8s apiserver  Prometheus    Harbor      Jenkins
   (GoDaddy…)      (CDN/DNS)    (多集群只读)    /Loki                    (流水线)
```

- **业务端口 8080**，**健康 + /metrics 独立在 8088**。分开是有意的：业务端口 hang 死时
  探活仍然可用，不至于把"卡住"表现成"进程没了"。
- 数据有两种来源：**采集**（定时同步进库，页面读快照，快）和**直连**（实时诊断、
  日志查询，慢但新）。凡是标注"实时"的功能走后者。

### 批量续费

域名页 →「批量续费」，粘一串域名进去（换行/逗号/空格都行，大小写和
`http(s)://` 前缀会自动规整）。刻意做成**两步**：

1. **检查** —— 只匹配不扣费，列出每个域名的状态：可续 / 台账里没有 /
   数据源不支持写回 / 列表里重复，以及当前到期日和预计续到哪天
2. **确认续费** —— 看清楚了再点，二次确认里写明"几个域名 × 几年"

一步到位在这里是危险的：打错一个字母会静默跳过某个该续的域名，
而"跳过"在一屏结果里最容易被眼睛滑过去。

其他约束：一次最多 50 个（安全阀，不是技术限制）；执行时**串行**且域名之间
间隔 3 秒（并发或连打注册商写接口容易触发限流，出错时也更难查清到底扣了几笔）；
重复域名只处理一次；服务端会核对前端确认时看到的可续数量，
对不上说明台账在这期间变过，拒绝执行并要求重新检查。

**执行是异步的**：点确认后立即返回任务号，续费在后台跑，前端 3 秒轮询一次进度。
弹窗可以随时关掉，任务照跑。这不只是体验——同步等会撞前端 30 秒超时，
届时前端已断开而后端还在扣费，用户看到的结果和实际扣费对不上。

#### 三种结果，含义完全不同

| 状态 | 含义 | 该怎么处理 |
|---|---|---|
| **已续费** | 厂商正常响应，有订单号 | 无需处理 |
| **待核对** | 响应丢了，但回查到期日确认**钱已经扣了**，没有订单号 | 去 GoDaddy 账单按日期找订单号；**切勿重试** |
| **失败** | 已回查确认**没扣费** | 看原因；瞬时故障系统已自动重试过，仍失败多为凭据/归属问题 |

「待核对」这个状态是必须的：GoDaddy 续费是**非幂等写**，请求超时/中断/5xx 时
订单很可能已经受理并扣款，只是响应没回来。把它简单报成"失败"有两个恶果——
台账没记（对不上账单），以及人以为没扣去重试，那就真扣两笔了。

#### 自动重试的门槛

失败后系统**可能**重试（最多 2 次，退避 8 秒），但门槛很高，两条必须同时成立：

1. 回查厂商到期日，**读到了**且还是旧值 → 确认这次没扣费。
   注意"查不出来"不算：那种情况一律不重试。
2. 错误是瞬时类（限流 / 超时 / 5xx）。403、凭据错这类重试多少次都一样。

结果里会显示「试了 N 次」，对账时能看出这个域名不止发过一次请求。

续费属于**不可回滚**操作（钱已经花出去了），但每一笔都会落
`domain_renewals` 台账（报价/订单号/到期前后/操作人）并记审计。
「待核对」那类也会落台账，raw_resp 里写明是"响应失败但经到期日核对确认已续费"。

### 域名到期日从哪来

两个定时任务分工，别只看其中一个：

| 任务 | 数据源 | 特点 | 管哪些域名 |
|---|---|---|---|
| `registrar_expiry_sync` | 注册商 API | **续费当场生效**，权威 | 数据源里配了凭据的 |
| `refresh_expiry` | RDAP/WHOIS | 滞后几小时到一两天，且易被限流 | 手工录入、不属于任何数据源的 |

刚续完费却看到台账还是旧到期日，多半是只跑了 WHOIS 那个。
**手动执行**：系统 → 定时任务 → 对应行的「立即运行」。

## 3. 权限模型

权限**不在 CMDB 里配**，在运维平台统一分配，CMDB 只负责消费权限码。
三层控制：**菜单级**（能不能看这个页面）、**按钮级**（能不能做这个操作）、
**接口级**（后端逐个请求校验）。前端只做显隐，真正的拦截全在后端。

### 权限码约定

```
menu:cmdb              父权限，没有它连门都进不来
menu:cmdb_<页面>       菜单权限，如 menu:cmdb_k8s_nodes
cmdb:<动作>            按钮权限，如 cmdb:manage_dns
```

共 **33 条菜单权限 + 24 条按钮权限**。几个刻意拆开的：

| 权限码 | 为什么单独成码 |
|---|---|
| `cmdb:manage_dns` | 直接写云端 DNS，改错就是线上解析挂。给"域名管理"不等于给这个 |
| `cmdb:issue_cert` | 真的调 CA，有速率限制，滥用会把域名打进 Let's Encrypt 封禁窗口 |
| `cmdb:manage_clusters` | 纳管要填 kubeconfig/SA，等于往 CMDB 塞一把生产集群钥匙 |
| `cmdb:manage_integrations` | 各系统的凭据，改了就等于换钥匙 |
| `cmdb:manage_mcp` | MCP Token 是机器身份、不受 RBAC 约束，拿到即可读全量数据 |
| `cmdb:k8s_diag` | 虽是只读，但绕过快照直连生产 apiserver，日志里可能有业务数据 |
| `cmdb:run_task` vs `cmdb:manage_cron` | 值班要能补跑一次同步，但不该能改 cron 表达式去打爆云厂商配额 |
| `cmdb:revert_change` | 能改 ≠ 能把别人的改动撤掉 |

### 预置角色模板

| 角色 | 大致范围 |
|---|---|
| CMDB 只读 | 全部页面，除云成本/接入管理/操作审计；无任何写权限 |
| CMDB 资产管理员 | 域名/证书/CDN/云资源台账维护；**不含** DNS 写入与证书签发 |
| CMDB 集群管理员 | K8s 全部页面 + 体检 + 升级计划；**不含**集群纳管 |
| CMDB 成本分析 | 只看云成本与资源使用率 |
| CMDB 管理员 | 全部 |

> 模板只在角色**首次创建**时灌一次权限。管理员后续在界面上的调整不会被重启覆盖。

### 怎么给一个新同事开权限

1. 运维平台 →「用户管理」建号（或 SSO 同步过来）
2. →「角色管理」，选一个 CMDB 角色模板，或复制一个再按需勾选
   （菜单权限树里找 **CMDB**，操作权限找 **[CMDB]** 分组）
3. 确认该角色关联了 **cmdb** 这个外部应用（「应用管理」里配）——
   只有菜单权限没有应用准入，登录会被拒
4. →「用户管理」把角色分配给这个人
5. 他从运维平台点 CMDB 图标进来即可。**权限调整不用重登**，
   刷新页面或点无权限页上的「刷新我的权限」就生效

### 开启 / 关闭单点登录

登录页显示「未开启单点登录」，或从运维平台点进来报错，就是这里没配。

**在页面上配，改完立即生效，不用重启**：
系统 →「基础配置」→「单点登录」，填运维平台**后端**地址（如
`http://opsplatform-backend:8080`）并打开开关。

环境变量 `PORTAL_API_URL` 仍然有效，但只作兜底：页面上把开关关掉，
就算环境变量还配着也一律拒绝 SSO——**开关的优先级高于地址来源**。

> SSO 用户和同名本地账号是**两条独立记录**（`UNIQUE(username, auth_source)`）。
> 这不是冗余：本地账号在权限中间件里是全放行的兜底身份，
> 让 SSO 用户挂到本地记录上，等于谁在运维平台叫这个名字谁就拿到 CMDB 完整权限。
> 用户管理页会标出每个账号是「本地」还是「运维平台」。

### 排查权限问题

- 进不去，提示"没有 CMDB 的访问权限" → 缺 `menu:cmdb`
- 进不去，提示"角色未被授予访问 CMDB" → 缺 `role_external_apps` 里的 cmdb 关联
- 提示"权限服务暂不可用" → 运维平台不可达。**这是故意 fail-closed 的**：
  问不到答案不能当成"允许"
- 某个按钮看不见 → 缺对应 `cmdb:*` 按钮权限
- 接口 403 且返回 `need: xxx` → 那个 `xxx` 就是缺的权限码
- 本地 `admin` 账号不受权限约束，是运维平台挂掉时的兜底通道

## 4. 审计与回滚

**所有人工写操作都留痕，所有数据行变更都保存变更前的完整快照。**

### 记什么、不记什么

记：人（或 AI 经 MCP）主动做的决定——改配置、写 DNS、纳管集群、跑任务，
包括**失败的和被权限拒绝的**（谁在试探什么，本身就是要看的）。

不记：定时同步拉回来的数据差异。K8s 每 120s 全量同步一轮，
一次能产生上万行 diff，一周就把表撑死；那些属于"系统观测到的世界变化"，
不是"人做的决定"，它们有 `task_runs` 和事件中心承载。

### 怎么查

- **按人/时间查**：系统管理 →「操作审计」，可按操作人、对象、动作类型、
  结果、来源（运维平台/本地/AI/系统）、时间段筛选
- **按对象查**：直接打开该对象的详情页，底部「变更历史」时间线——
  比去审计页按关键字翻实用得多

点「详情」看字段级 diff：红色是变更前，绿色是变更后，**没变的字段不显示**。
敏感字段（密码/token/凭据）只显示"已变更"，值不出库；URL 类字段脱敏到 host。

### 怎么回滚

在变更详情里点「回滚这项」。三种情况：

| 级别 | 场景 | 行为 |
|---|---|---|
| 可直接回滚 | 纯本地库改动（台账、配置、费率、通知人…） | 二次确认后反向写回。删除的记录会整行插回来 |
| 不支持一键回滚 | 会改动外部系统（DNS 解析） | 给出原值，去对应页面手动改回；改完自动留下新审计 |
| 不可回滚 | 证书签发、同步、Token 重置、手动跑任务 | 按钮置灰，鼠标悬停显示**具体原因** |

**冲突检测**：回滚前会拿当前数据和"当时改完的样子"比对。如果这条记录后来
被别人改过，回滚会被拦下并告诉你**冲突字段**和**最近是谁改的**，
确认无误可以强制回滚。没有这一步，回滚就是个静默覆盖他人改动的工具。

回滚本身也是一次变更，同样留审计，所以**回滚还能再被回滚**。

### 保留期

默认**永久保留**。要启用清理，在基础配置里设：

- `audit_retention_days` —— 操作流水保留天数，`0` = 永久
- `audit_changes_retention_days` —— 变更明细保留天数，`0` = 永久

审计表没有删除接口，管理员在界面上也删不掉，只有到期清理任务能删，
且清理动作本身也记一条审计。容量参考：约 6MB/天、2GB/年。

## 5. 部署

```bash
# 镜像（本地 Harbor）
localhost:8070/opsplatform/opsplatform-cmdb-backend:<版本>
localhost:8070/opsplatform/opsplatform-cmdb-frontend:<版本>

kubectl apply -f k8s-deploy.yaml     # namespace: opsplatform
```

### 环境变量

| 变量 | 说明 |
|---|---|
| `MYSQL_HOST/PORT/USER/PASSWORD/DATABASE` | 数据库连接 |
| `JWT_SECRET` | 会话签名 |
| `CMDB_AES_KEY` | **凭据与审计快照的加密密钥**。换了它，已存的凭据和变更快照都解不开 |
| `PORTAL_API_URL` | 运维平台后端地址。留空 = 关闭 SSO，只剩本地 admin |
| `SESSION_HOURS` | 会话有效期，默认 24 |
| `ADMIN_PASSWORD` | 首启种子 admin 的密码，默认 admin123 |
| `PORT` / `HEALTH_PORT` | 默认 `:8080` / `:8088` |
| `TZ` | 建议 `Asia/Manila`，与 DSN 的 `time_zone` 保持一致 |

### 数据库变更

一律走 `database/migrations/`，**禁止手改生产库**。runner 幂等（列/索引已存在会跳过），
pod 重启即可自愈补齐。

> ⚠️ 仓库根 `.gitignore` 里有 `*.sql`，**新增迁移必须 `git add -f`**，
> 否则进不了 git（镜像靠 `go:embed` 不受影响，所以本地跑得好好的，别人拉下来就少了）。

## 6. 本地开发

- 前端 <http://localhost:30829>，后端 API 走同端口的 `/api/`
- MySQL 走 30306（k8s-proxy 固定端口，不要临时 port-forward）
- 前端构建**必须传版本号**，否则界面上显示 `dev`，排障时看不出前端版本：
  ```bash
  docker build --build-arg VERSION=v184 -t <镜像>:v184 .
  ```
- 版本规则：每次构建 +1，**以 `k8s-deploy.yaml` 里的 tag 为准**

### UI 约定

- 禁止 `window.confirm/alert/prompt`，统一用 `appStore.showConfirm`
  （注意它取消时是 **reject**，要 `try/catch`）
- 弹窗不能点遮罩关闭：`close-on-click-modal=false`
- **三态纪律**：加载失败必须显式报错，不能退化成空数据。
  新页面一律用 `useLoadState` + `LoadError`——
  监控类系统最危险的失效模式就是故障时告诉运维"一切正常"

## 7. 排障

| 现象 | 先看哪 |
|---|---|
| 全站接口卡住/超时 | 数据库。DSN 有 30s 读超时，卡死的查询会失败而不是拖成 504 |
| Pod 反复重启 | `livenessProbe` 只探 `/health`（不查库）。若 DB 故障不该重启 Pod |
| 某接口 403 | 响应里的 `need` 字段就是缺的权限码 |
| 新加的接口直接 403 | 忘了在 `handlers/perm.go` 登记。**启动日志会列出未配置权限的路由** |
| 某次变更回滚不了 | 详情里的"不可回滚原因"。多半是外部系统类或该接口没登记变更捕获 |
| 页面数字对不上 | 先确认是台账口径还是探测口径——总览页两块是**不同对象集**，不该相等 |

日志是 JSON 行格式，带 `trace_id`，可与审计记录互相对照。
启动时有两个自检，**建议每次发版扫一眼**：

```
权限映射自检通过，241 条路由全部有规则
变更捕获自检通过，107 条写接口全部登记
```

任何一条报 WARN 都会把具体路由列出来。
